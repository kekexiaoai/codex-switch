# Codex Switch 状态栏快切与统一主窗口设计

## 背景

当前产品采用 macOS 状态栏弹层承载账号摘要、账号列表、设置入口和部分重操作。随着账号数量增加，状态栏面板会变长，账号项扫描成本上升，小屏设备上的可用性也会明显下降。现有实现已经通过滚动容器和最大高度限制避免无限拉长，但它本质上仍然把“快速切换”和“完整管理”混在同一个面板里。

同时，当前桌面端还存在多个独立窗口，例如设置、Provider Sync、状态/诊断等。这种结构在功能较少时可以接受，但从长期看不利于统一心智模型，也不利于未来用 Rust 进行跨平台重构。

本设计的目标，是把状态栏收敛为“快速切换入口”，把完整管理能力统一收敛到一个主窗口中，并且用平台无关的交互契约来约束行为，确保后续 Swift 版与 Rust 跨平台版都能实现一致体验。

## 目标

- 将状态栏入口重新定义为“快速切换 + 少量快捷动作”，不再承担完整账号管理职责。
- 保留状态栏的高频价值：快速查看当前账号摘要、快速切换账号、快速打开主窗口。
- 引入统一主窗口，集中承载账号管理、Provider Sync、设置、状态/诊断等重操作。
- 明确“账号排序的唯一真源”来自主窗口的账号管理页，状态栏快切区只做展示和切换。
- 为后续 Rust 跨平台重构输出平台无关的行为定义，而不是绑定到某个 Apple 专属控件。

## 非目标

- 本次设计不追求把所有功能重新做成首页仪表盘。
- 本次设计不引入复杂分组、智能排序或多维筛选作为快切区第一版能力。
- 本次设计不要求状态栏快切区承担删除、激活、导入、同步等重操作。
- 本次设计不强制使用某一种具体跨平台 UI 框架。

## 总体结构

产品采用“两层入口”结构：

- 状态栏：高频、轻量、即时。
- 主窗口：低频但完整、可管理、可整理。

状态栏只保留当前账号摘要、快速切换入口、打开主窗口以及少量全局动作。账号管理、排序、删除、Provider Sync、设置、状态/诊断等内容全部收敛到统一主窗口。

## 状态栏信息架构

### 一级菜单

一级菜单保留以下内容：

- 当前账号摘要
- `快速切换`
- `打开主窗口`
- 刷新用量
- 设置
- 退出

其中：

- `打开主窗口` 用于进入统一主窗口，默认落到 `账号` Tab。
- `账号管理窗口` 的概念在产品层面升级为“主窗口”，不再把账号管理视为一个独立孤岛窗口。
- 一级菜单不再直接渲染长账号列表。

### 快速切换区域

`快速切换` 不采用“切到二级页面再返回”的模式，而采用“锚定在一级菜单旁的二级浮层”模式。它在视觉和交互上接近原生二级菜单，但规格不绑定到任何平台专属 submenu 控件。

平台无关定义如下：

- 当指针 hover 到一级菜单中的 `快速切换` 项时，在其旁边显示一个锚定浮层。
- 浮层用于展示账号快切列表。
- 鼠标移出一级菜单项与浮层整体区域后，浮层自动收起。
- 点击菜单外部时，关闭整个状态栏菜单体系。

## 快速切换浮层设计

### 交互目标

快速切换浮层只做两件事：

- 查看账号用量
- 点击切换账号

所有重操作都不进入快切浮层。

### 列表结构

快切浮层展示全部账号，支持内部滚动。

- 浮层有最大高度。
- 当账号过多时，浮层内部滚动。
- 不分页，不只显示前 N 个，不分组。
- 排序完全跟随主窗口账号页，不做二次排序。

### 账号行设计

账号行采用单行紧凑布局，以避免邮箱长度不同导致的高度跳动和扫描节奏紊乱。

单行固定结构：

- 邮箱
- 账号类型角标
- `5H` 用量胶囊
- `7D` 用量胶囊

设计原则：

- 邮箱仍是主要识别信息，占据主视觉重心。
- 类型以角标形式展示，减少文本噪音并增强识别。
- `5H` 与 `7D` 不能只保留裸百分比，必须通过标签化胶囊明确区分。
- 当前账号仅通过勾选或高亮表示，不置顶、不跳位。

### 行为定义

- 点击整行立即切换账号。
- 当前账号保留在排序中的原位置，不因为“当前选中”而改变列表顺序。
- 快切浮层中不提供删除、激活、导入、管理入口等额外操作。
- `打开主窗口` 保持在一级菜单，不进入快切浮层。

## 统一主窗口设计

### 结构

产品引入统一主窗口，作为所有完整功能的主承载界面。

主窗口使用顶部 `segmented tabs` 作为一级导航，不采用左侧栏导航。这样可以更充分利用空间，并且在当前模块数量可控的前提下保持结构清晰。

首批 Tab：

- `账号`
- `Provider Sync`
- `设置`
- `状态`

### 入口规则

- 从状态栏的 `打开主窗口` 进入时，默认打开 `账号` Tab。
- 从特定入口进入主窗口时，可以定向打开对应 Tab。
- 后续不再为 `Provider Sync`、`设置`、`状态` 各自保留长期独立窗口作为主产品结构。

### 主窗口职责

统一主窗口承载所有完整能力：

- 账号查看
- 账号排序
- 账号删除
- 账号激活/切换
- 用量查看
- Provider Sync
- 设置
- 状态/诊断

其中，`账号` Tab 是账号顺序的唯一真源。

## 账号排序模型

### 排序原则

- 默认按添加顺序排序。
- 快切浮层顺序完全跟随 `账号` Tab 的顺序。
- 快切区不做按用量、最近切换、当前账号置顶等二次改写。
- 切换账号本身不改变顺序。

### 排序交互

账号页需要支持手工排序。

建议能力：

- 拖拽排序
- 上移 / 下移作为兜底交互

这样既能满足桌面端的自然交互，也能为未来跨平台实现提供更稳的降级路径。

## 数据模型约束

为了让 Swift 版和未来 Rust 版复用一致规则，账号顺序必须通过显式持久化字段保存，而不能依赖隐式顺序。

建议新增持久化字段：

- `manualOrder` 或 `sortIndex`

规则如下：

- 新账号导入时默认追加到末尾。
- 调整顺序时直接更新该字段。
- 删除账号后，顺序重新压紧，避免编号稀疏。
- 快切列表消费的是已排序账号数组，不再在 UI 层重新推断顺序。

快切展示模型只关心渲染所需字段，例如：

- `id`
- 显示邮箱
- 类型标签
- `5H` 百分比
- `7D` 百分比
- 是否当前账号

## 平台无关交互契约

为支持未来 Rust 跨平台重构，本设计只定义行为和布局契约，不绑定 SwiftUI、AppKit 或原生 macOS submenu 控件。

核心契约如下：

- 应用包含一个状态栏入口和一个统一主窗口。
- 状态栏一级菜单包含摘要、快速切换入口、打开主窗口和少量工具动作。
- `快速切换` 通过 hover 激活一个锚定在一级菜单旁的二级浮层。
- 快切浮层内部展示可滚动账号列表。
- 主窗口是所有重操作的唯一承载面。
- 主窗口采用顶部一级 tabs 切换模块。
- 账号顺序由主窗口账号页决定，状态栏只读该顺序。

换言之，规格定义的是：

- `single main window`
- `top segmented tabs`
- `quick switch overlay`

而不是某个特定平台控件名称。

## 异常与边界情况

### Hover 稳定性

快切浮层必须避免因为 hover 区域过窄而频繁闪烁。

建议行为：

- 一级菜单项与快切浮层之间保留连续 hover 可达区域。
- 浮层收起使用短延迟，而不是鼠标一离开就立即消失。

### 切换失败

- 点击账号行后立即发起切换。
- 切换成功后，关闭整个菜单。
- 切换失败时，不改变当前账号高亮。
- 错误反馈返回到一级菜单层显示，不在快切浮层中塞复杂错误状态。

### 数据缺失

- 某个账号缺少 `5H/7D` 用量时，账号仍然显示。
- 缺失值使用稳定占位，如 `5H --`、`7D --`。
- 类型未知时使用默认角标样式和默认文案。

### 大列表

- 快切浮层允许展示全部账号。
- 当账号过多时，通过内部滚动承载，而不是扩展外层菜单高度。
- 第一版不强制在快切浮层加入搜索。
- 如果未来需要搜索，优先加在主窗口账号页中。

## 测试与验收标准

### 体验验收

- 一级菜单不再因为账号过多而承担完整长列表。
- hover `快速切换` 能稳定拉起二级浮层。
- 从一级菜单项移动到浮层时不会频繁闪烁或误收起。
- 快切浮层中任意账号都能通过滚动到达。
- 当前账号仅高亮，不改变原排序位置。
- `打开主窗口` 位于一级菜单，不进入快切浮层。
- 主窗口使用顶部 `segmented tabs` 承载 `账号`、`Provider Sync`、`设置`、`状态`。

### 数据验收

- 新导入账号默认追加到顺序末尾。
- 调整主窗口账号顺序后，快切浮层顺序同步变化。
- 切换账号不会改变账号排序。
- 删除账号后顺序字段保持连续。

### 跨平台验收

- 文档中的所有交互约束都能以平台无关方式表达。
- 不依赖原生 macOS submenu 作为唯一实现手段。
- 后续 Rust 跨平台版本只要实现相同行为契约，即视为满足设计要求。

## 推荐实施顺序

1. 先把状态栏当前长列表改造成“一级菜单 + 快切浮层”的结构。
2. 抽离账号排序真源，引入显式顺序字段。
3. 新建统一主窗口容器，先接入 `账号` Tab。
4. 将 `Provider Sync`、`设置`、`状态` 逐步并入主窗口。
5. 最后清理旧的多窗口路径，使产品结构收敛到“状态栏 + 主窗口”。

## 结论

本设计将 Codex Switch 从“状态栏承担一切”的形态，重构为“状态栏负责快切，主窗口负责完整管理”的双层结构。它既解决了账号数量增多导致的长列表与小屏可用性问题，也为后续 Rust 跨平台重构提供了稳定的产品契约。最关键的原则是：

- 快切只做快切
- 排序真源在账号页
- 重操作进入主窗口
- 规格定义行为，不定义平台控件
