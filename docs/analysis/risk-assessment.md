# Codex Switch Tauri 重构风险评估

## 高风险

### 1. `.codex` 兼容性回归

风险：

- 任何路径、命名、写入时机、原子替换行为偏差，都会导致现有用户数据不可用或切换失败。

缓解：

- 将 `.codex` 相关行为作为 Rust 集成测试核心覆盖面
- 优先迁移 `paths`、`auth`、`switch`、`usage` 服务

### 2. 浏览器登录切换

风险：

- 现有设计已转向“桌面自持登录”，Tauri 需要重新落实浏览器打开、完成检测、超时、取消、失败提示。

缓解：

- 引入独立 `desktop_login` 服务
- 先通过测试定义状态机，再接入浏览器与文件监听

### 3. Provider Sync 数据安全

风险：

- `config.toml`、`rollout-*.jsonl`、SQLite 三层写入需要备份、回滚、锁。

缓解：

- 先写纯 Rust 单元/集成测试
- 保持“备份先行、失败回滚”约束

## 中风险

### 4. Tauri 托盘与跨平台差异

风险：

- macOS、Windows、Linux 的托盘能力不一致。

缓解：

- 主窗口作为第一入口
- 托盘作为增强能力，而不是唯一依赖

### 5. 去 Web 化 UI 落地

风险：

- 使用 React/shadcn/ui 容易默认生成 SaaS 风格界面，偏离桌面工具质感。

缓解：

- 先建立桌面 design tokens 与壳层组件
- 统一压缩间距、降低色彩和圆角，避免 marketing/dashboard 模式

## 低风险

### 6. 打包链路迁移

风险：

- 由 Xcode 脚本迁移到 Tauri bundler，需要更新时间线与发布文档。

缓解：

- 在功能收口后统一处理

## 验收红线

- 不允许破坏 `.codex` 兼容性
- 不允许托盘承担完整管理职责
- 不允许主窗口呈现明显 Web/SaaS 仪表盘风格
- 不允许把终端作为正式登录主路径
